RedactGuard — redact a photo or a message on your Android, offline, before it leaves the phone

An open source app that destroys the pixels you point at instead of covering them, throws the file's metadata away by re-encoding the picture rather than scrubbing it tag by tag, and then shows you what it removed. It does not tell you the result is safe to send, because nobody can.

The difference between the first two rows and the third is whether the information was hidden or replaced. Everything else about redaction tools — the ones that ship a "one-click" PDF redaction, the ones that print a confidence percentage — follows from getting that distinction wrong.

What runs on the device

  • Two fills. Solid writes a flat colour into the region; mosaic downsamples it and draws the small bitmap back with filtering off, which is what leaves the squares. Both write into the copy this app holds, not onto it.
  • A proof. Each region's pixels are sampled before the fill and again after, so the app prints the share that actually changed instead of asserting it. A rectangle that missed the image shows up as a number.
  • A metadata reading. 27 watched tag names are read one by one and listed with their values — position, fix time, device make and model, lens, ISO, the shooting clock and the UTC offset, artist, copyright, comments, and the offset and length of an embedded thumbnail of the picture.
  • A re-encode. The output is a new JPEG from pixels the app already owns, so the EXIF container is gone rather than emptied. The produced bytes are read back and the surviving count is printed, including the case where it is not zero.
  • Fourteen text shapes. Tried in a fixed order, each with a stated confidence, with two of them carrying a sanity check rather than a wider net: a card number must pass Luhn, and a twelve-digit Malaysian identity number must begin with a date that could have happened.

Everything the app did not match is printed too, next to the list. That column is the honest part of the screen: an empty finding list means fourteen patterns did not fire, not that a reader cannot work out who you are.

What it will not say

  • That a picture or a message is safe to send. No match is not evidence of no match.
  • That a mosaic is unrecoverable. It prints which block size you are on and says when that setting is too weak to hide what it looks like it hides.
  • A percentage describing how anonymous a result is. There is no denominator for that number.
  • What lies under a filled region. Nothing can, which is the entire point.
  • That its optional model pass is complete. It sees only what the local shapes failed to remove.

Permissions, stated

None are requested. The picture comes in through the photo picker or the share sheet; saving goes through the system's create-document sheet; sharing hands over a single FileProvider URI that expires with the recipient. The picked file is copied into the app's cache once — a shared content stream cannot reliably be opened twice — and that copy is deleted as soon as it has been decoded. The original in your gallery is never modified, re-saved or deleted, and there is no history screen, queue, thumbnail database or gallery index for a half-finished redaction to appear in. With Android's backup flag set off, nothing in private storage rides out into a cloud backup or an adb backup.

And the limit worth remembering. A redaction that only touches pixels cannot remove what a reader already knows. A name, a job title, a relationship, a routine, a doorway, a view — none of those are formats, so none of them are catchable by a pattern, and a tool that printed an all-clear on them would be the dangerous version of this app.

The other limit: transparency is flattened onto white and HEIF decodes only where Android ships a decoder, because the output is always a re-encoded JPEG. Both are printed in the README rather than discovered at the moment you needed them.

Build and run it

git clone https://github.com/wonghanz/RedactGuard
cd RedactGuard
export ANDROID_HOME=/path/to/Android/sdk
./gradlew --no-daemon assembleDebug
# → app/build/outputs/apk/debug/app-debug.apk

No credential is in the repository, no service of ours is involved in the build, and the local passes need no configuration of any kind.

Frequently asked

Does drawing a black rectangle over a photo actually redact it?

Not if the rectangle is a layer — the original pixels stay underneath. A redaction has to replace pixels, which is the only thing this app's apply step does, and it then measures how many changed.

How do I strip GPS and EXIF from a photo on Android without uploading it?

Pick the photo, read the tags it admits, then Save or Share the redacted copy. Saving writes a fresh JPEG, so the metadata leaves with its container; the app re-reads the output and prints how many watched tags survived.

Is mosaic better than a black box?

Only at a coarse block size, and the app tells you which one you are on. Solid fill is the only option here that removes information instead of hiding it.

Does it detect faces automatically?

No, and there is no switch for it. A wrong "nothing here" is the one mistake you cannot undo after you press send, so the app leaves pointing at pointing.

Can I undo a redaction?

Not inside the copy the app made — there is no hidden original to reveal. Your gallery file is untouched, so start again from that.

Does it redact text inside a screenshot, or a PDF?

Neither. There is no OCR, so visible text stays visible until you box it, and a PDF would have to be rebuilt to be redacted honestly. One image or one block of text, on a phone.

Do I need an account or an API key?

No. Everything above runs in airplane mode. A key you type yourself only unlocks a second read of what the local pass failed to remove.
